[EP-001] fix a harness defect that silently reopened closed nodes

DEFECT FOUND BY VERIFYING RATHER THAN ASSUMING. After EP-001 was closed and tagged
green/EP-001, a routine check reported "EP-001: PENDING" and the graph regressed to
"NEXT EP-001" - it would have re-dispatched a finished node.

Root cause in scripts/ledger.sh: the status command was

  grep -E "| <node> |" LEDGER.md | tail -1 | grep -q NODE_DONE

It inspected only the LAST event for a node, so any event appended after closure (a
correction, a footnote, a re-run note) silently reopened it. EP-001 was closed, then
an EVIDENCE_INDEX_FIXED note was appended, and the node appeared open again. EP-000
only escaped because nothing followed its close. Every remaining node was exposed to
the same corruption.

FIX: closure is now a historical fact. A node is DONE if a NODE_DONE exists for it
and no REOPEN was appended after the last NODE_DONE. Reopening requires a new explicit
reopen subcommand, so it can never happen by accident. Argument validation and a usage
message were added, which the one-line original lacked.

PROVEN DISCRIMINATING, not merely changed:
  - EP-002 (never closed) still reports PENDING;
  - EP-001 stays DONE after a fresh event is appended;
  - a deliberate reopen flips it to PENDING and moves the graph back to NEXT EP-001;
  - re-closing restores DONE and NEXT EP-002.

The full chain now reads EP-000 DONE, EP-001 DONE, EP-002 PENDING, EP-003 PENDING,
with graph-next reporting NEXT EP-002.
