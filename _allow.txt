[EP-003][M1] allow-list the three reviewed harness sentinels

The reality gate's rule 3 correctly flagged three lines in
src/infrastructure/database/provision.ts: the pinned CLI helper prints
"db provision: ok" and "db teardown: ok", which the gate treats as
sentinel-like output in production code.

This is a genuine false positive. Those sentinels are the helper's CONTRACT:
db-provision.sh and db-teardown.sh require the exact line before printing
their own sentinel, so the string is load-bearing, not simulated behaviour.

The gate's own design supplies the correct remedy: an explicit reviewed
path:line entry, never a wildcard. Three entries added, each with its reason.

PROVEN SPECIFIC, not merely silenced: a seeded `console.log('something: ok')`
in an unlisted production file still fails the gate with the offending file and
line named. The allow-list permits exactly three lines, not a class of lines.

Observed: reality gate: ok with "hits present and individually allowed";
full gate suite 0 failures.
