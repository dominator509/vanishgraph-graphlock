## 2. What the executor found, and why it refuses to call any of this a PASS

**The 484 IDs are entries in a prompt pack.** Each is an `<AGENTIC_PROMPT>` block written for an agentic
security-testing environment — role, authorization boundary, mandatory scope-discovery pass, methodology,
completion gate. **The delivered casebooks are templated stubs**: all 484 objects carry the same
`exact_commands: ["sh scripts/verify.sh"]`, the same oracle phrase (`real evidence or precise terminal blocker`)
and the same negative case. A harness that ran `sh scripts/verify.sh` 484 times would prove nothing per ID and
would print a sentinel over a placeholder, so it does not do that. Instead:

1. **The real definition is extracted** from the library the registry's `source_file` column names, and written to
   `.agent/evidence/EP-010/V-0NN/<ID>/definition.md` with its digest — evidence that the definition was read.
2. **The repository gate covering the same subject runs once per stage** (static analysis, security contract,
   secrets, supply chain, build, config, reality, unit, integration, smoke) and its raw output and digest are
   linked to every ID it covers. One execution cited for the IDs it covers is honest; the same command once per ID
   would be the same evidence repeated four hundred times.
3. **No ID is called `PASS`.** SPEC-006 §4.1 requires an executed oracle, a matched sentinel **and an executed
   negative case**; the negative case here is a paragraph inside a prompt that only an authorised agentic runner
   can execute. The ceiling for a mapped ID is therefore `PARTIAL`, and an ID needing active testing, a deployed
   target, or a runner this environment does not have is `BLOCKED_SAFETY`, `BLOCKED_ENVIRONMENT` or
   `BLOCKED_PREREQUISITE` with the field each requires.

## 3. Defects found in the harness itself, and fixed

| defect | how it was found | fix |
|---|---|---|
| Seven definitions reported "not located" (SUP-001…004, E2E-001…004) | the stages' own `ERROR` lines | the E2E library defines entries as **level‑1** headings (`# E2E-001 SOURCE: …`); the matcher demanded 2–4 hashes, and now locates **by ID first**, then by title. The SUP source is a **231-byte summary** with no per-ID method, so a summary source is used **as** a definition and labelled `summary-source`, producing `BLOCKED_PREREQUISITE` with the missing method named instead of a harness `ERROR` |
| Every re-run died with `definitionKind is not defined` | the re-run output | a `let` inside the extraction block is out of scope in the classification below it; declared outside, with the incident recorded in the script |
| `BLOCKED_ENVIRONMENT` written without the field SPEC-006 requires | the validator, once it began checking the **real** rows rather than only its fixtures | the executor now emits `provisioningAction` naming the manifest and the missing property |
| `BLOCKED_PREREQUISITE` reported as "not an edge in the dependency graph" | the same new check | the lookup was wrong, not the rows: a row names the **dependency** it waits on while the graph stores **edges**, so the check now requires the named dependency to be a **node** of the graph |
| Seven stale `dist-repro-*` directories from the pre-fix reproducibility implementation | a repository-wide search for a definition location | removed; the current tarball was verified to contain **0** `.agent/` entries, so the package allowlist claim from M1 still holds |

**Re-runs are recorded, not erased.** The seven withdrawn statuses were invalidated with a written reason
(`--invalidate`, recorded as `WITHDRAWN` transitions in `STATUS_TRANSITION_AUDIT.jsonl`), the ledger stayed
append-only, and the accounting counts the **latest** row per ID while reporting the superseded rows as their own
number (61 so far) — a duplicate with no recorded withdrawal is still a defect, and that is what the accounting
now checks.
