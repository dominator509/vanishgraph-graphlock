## 2. Long-running honesty (M4(b), DOD-038, VG-SHIP-020)

A soak, endurance, stress, fuzz or recovery-duration prompt is now classified **before** any gate mapping, and the
row carries the fields the plan names: `workload`, `plannedDuration` (parsed from the prompt, or stated as "not
declared in the prompt text"), `elapsedDuration` (`PT0S - not started: this campaign window cannot host the planned
duration`), `startedAt`, `heartbeatRef` (the stage checkpoint a real runner would heartbeat into),
`partialResultPath`, `completionEta`. **A five-minute run never passes a 72-hour requirement**, and the abbreviated
portion is never written as `PASS`.

## 3. Non-cascading continuation and the fields a blocker needs (M4(c), FALLBACK)

No `FAIL` occurred, and no blanket block was produced: 192 IDs are `BLOCKED_PREREQUISITE`, each naming the
capability it waits on **and** `dependencyEdgeRef` pointing at the edge in the dependency graph. Provider
entitlements are `BLOCKED_CREDENTIALS` **with the probe executed**: the `PREFLIGHT.md` row (`STRIPE_SECRET_KEY`,
`CLICK2MAIL_API_KEY`, `SEARCH_API_KEY`, `GITHUB_APP_ID`, `LOCAL_MODEL_ENDPOINT`), the probe script, its exit code
and its output are recorded as evidence (7 such rows). Production-touching prompts are `BLOCKED_SAFETY` **with the
scope clause named** (`VG-SCOPE-009`). Environments are `BLOCKED_ENVIRONMENT` with `provisioningAction` and
`scopeClause`.

## 4. Change invalidation (M4(d), DOD-040, VG-SHIP-005)

The executor's classification changed **after 103 statuses existed**, which is exactly the case the rule is for:
the artifact surface changed, so the epoch **rolled** — `FORGE-SPEC-2` → **`FORGE-SPEC-3`** — with the reason, the
changed surfaces and the revocation recorded in `.agent/verification/state/CHANGE_INVALIDATION_GRAPH.md`, and the
older rows retained in the ledger as history but no longer counted. The revocation was measured before the
re-run: **165 rows covering 103 IDs**, of which **0 were `PASS`** (they were PARTIAL and blockers). Every stage was
then re-run under the new epoch, so the whole set is accounted inside one epoch rather than stitched across two.

- **No ID passed.** 265 are `PARTIAL`: the covering gate ran, and the prompt's own scope discovery, methodology
  and negative case — which only an authorised agentic runner can execute — did not.
- **No long-running workload ran**: 1 ID is `DEFERRED_LONG_RUNNING` with its planned duration and the reason the
  campaign window cannot host it.
- **Seven IDs are blocked on provider entitlements**, with the probe exit codes as evidence rather than an
  assertion that the providers are unavailable.
- **`accounting: 484/484` is not claimed**; the remaining 14 IDs belong to stages V-020 and V-021.
- `RELEASE_GATE.json` remains `INCONCLUSIVE` / `FORGE_ONLY`.
