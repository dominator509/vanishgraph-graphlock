[EP-005] review and correct the UI plan against the finalised stack

EP-005 was the one ExecPlan converted to Vite + React by scripted transformation
rather than authored against it. Read end to end and corrected. The earlier
transformation missed a whole class of remnants because it only matched `Next.js`
and `next.config` — it never matched the bare word `next`, `.next`, or the concept
of server rendering.

EXECUTION-BREAKING

1. The dependency block told the executor to install `next` and to add a
   `build:web` script running `next build` — in two places (the audit list and
   M1 CONTENT). Replaced with `react`, `react-dom`, `@tanstack/react-router`,
   `@tanstack/react-query`, `zod`, plus `vite`, `@vitejs/plugin-react`,
   `@vitejs/plugin-react`'s devDependency peers and `jsdom`; `build:web` is now
   `vite build`. The plan now states explicitly that there is no `next` dependency
   and why (ADR-007).

2. `ui/src/middleware.ts` was specified to perform "server-side refusal of a
   non-allowlisted filter value before rendering". A Vite SPA has no server
   runtime, so that file cannot exist and the requirement cannot be met there.
   Corrected: the authoritative refusal of a PII-bearing path or query is the
   API's (SPEC-004 VG-UI-005 places it server-side; SPEC-003 §7.1 implements it, in
   EP-004). EP-005 contributes the client-side guarantee that such a URL is never
   constructed, plus the contract test that proves it, and records the server half
   as BLOCKED_PREREQUISITE rather than claiming it.

3. Recovery instructions said `rm -rf .next` and treated `.next` as the build
   output. There is no `.next`; the Vite output is `ui/dist`.

INCORRECT COUNTS

4. The plan asserted "24 declared routes" in eight places. SPEC-004 §1 declares
   **25**. SPEC-004 makes no numeric claim, and EP-005's own route list already
   matched SPEC-004 exactly — only the number was wrong, and it originated in the
   authoring prompt rather than the specification. Corrected to 25.

VITE-EQUIVALENT REWRITES (the concept, not just the word)

5. Eight references to server rendering were replaced with what a Vite SPA
   actually does: the copy-lint gate scans the built browser bundle plus the built
   static HTML shell (`ui/dist/index.html`), and the contract suites assert against
   render-to-static-markup fixtures produced by `react-dom/server` under JSDOM. The
   `server payload` in the redaction milestone became the API response payload.

CONGRUENCE GAPS CLOSED

6. Route-notation normalisation was unspecified. SPEC-004 declares dynamic segments
   as `[caseId]`; TanStack Router's file convention is `$caseId` and its generated
   pattern is `/portal/cases/$caseId`. The manifest equality test would have failed
   for a reason unrelated to a missing route. The plan now requires the emitter to
   normalise `$param` to `[param]` before comparison, with its own unit assertion.

7. Gate error messages still said `ep005 ui gate: FAIL` in six places while the
   sentinel was already `gate-ui: ok`. All six corrected.

8. `tsconfig.ui.json` was listed under "Modified:" while annotated "(created)".
   Moved to Created.

ALSO FIXED (my own error, found by this review): TESTING.md listed `tests/ui/`
among the pure suites, but EP-005's `tests/ui/**` are Playwright specs requiring a
browser and the built application. Moved to a browser-dependent row, with a note
that they are `*.spec.ts` so the unit stage's `find -name '*.test.ts'` does not
sweep them in — and that this must not be relied on by accident.

VERIFIED: EP-005 now has zero Next.js, `.next`, server-render, `src/ui`, `ep005`
or "24" references. Structure intact — 8 milestones, 14 sections, all nine grammar
keywords matching, zero boxes checked. All 11 ExecPlans pass the structural audit
(91 milestones). All gates pass. Pack-wide stale references are limited to EP-000's
intentional ADR-007 documentation and EP-004's `page.nextCursor` pagination field.

NOT CLAIMED: the UI does not exist. Nothing in this change set builds, runs or
tests a single screen.
